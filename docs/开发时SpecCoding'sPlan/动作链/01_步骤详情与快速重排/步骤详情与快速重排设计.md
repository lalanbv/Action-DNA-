# 步骤详情与快速重排设计（Qt/tk 统一）

## 1. 背景与问题

动作链页面选中步骤后的「步骤详情」面板存在两类问题：

1. **Qt 端信息缺失（bug）**：`QtActionChainPropsMixin._show_step_props`（`src/panel/qt_backend/pages/action_chain_props_mixin.py`）只渲染「类型胶囊 / `#序号/总数` / 启用勾选 / 备注输入 / 4 个操作按钮」，**漏掉了 `step.describe()` 业务描述行**——这正是「什么信息也看不到」的直接原因。对照 tk 端 `StepPropertyPanel.show_step` 是有这一行的。
2. **参数不可见**：两端都只靠 `describe()` 单行摘要，坐标 / 阈值 / 按键 / 等待时间等关键参数无法在面板直接看到，只能双击打开编辑对话框。
3. **重排手段单一**：`_move_step(±1)` 只能逐格上下移动（且底层 `move_step` 是 swap 语义，见 §4），无法直接改序号、拖拽、批量或置顶置底。

## 2. 目标

- **修复** Qt 详情面板漏渲染 `describe()` 的 bug。
- **增强** 详情面板：摘要 + 关键参数表（默认展开）+ 全部字段（默认折叠）+ 启用 / 备注。
- **新增** 快速重排：输入目标序号确定移动、拖拽排序、多选批量上下移、置顶 / 置底按钮；保留 ↑↓ 逐格移动；新增「复制步骤」按钮。
- **统一**：Qt 与 tk 详情面板规格、字段定义、重排逻辑完全一致。业务逻辑层（Model / Controller / 配置）共用，纯渲染各自实现。

## 3. 架构分层

```
        ┌─────────────── 共用层（改一次，两端受益）───────────────┐
        │  ChainModel        + reorder_steps() / duplicate_step() │
        │  ActionChainController + 同名方法（_require_idle 保护）  │
        │  step_key_fields.py   集中配置：ActionType → 关键参数表  │
        │  step_param_view.py   共用：全部字段遍历 + 值格式化       │
        └─────────────────────────────────────────────────────────┘
                ↑ 调用                          ↑ 调用
   ┌────────────┴───────────┐          ┌────────┴─────────────┐
   │ Qt 详情面板 / 列表      │          │ tk 详情面板 / 列表     │
   │ 规格、字段、交互完全一致 │          │ 规格、字段、交互完全一致│
   └────────────────────────┘          └──────────────────────┘
```

**取舍**：重排逻辑 / 参数定义放共用层（单一事实来源，天然统一）；纯渲染 Qt / tk 各自实现（框架差异无法共用），但严格按同一规格表。

**关键事实**：Qt（`self._model`）与 tk（`self.model`）共用同一个 `ChainModel` 与 `ActionChainController`（`src/panel/models/chain_model.py` / `src/panel/controllers/action_chain_controller.py`），业务层扩展一次两端都受益。

## 4. Model / Controller 变更（共用层）

### 4.1 现状陷阱：`move_step` 是 swap 语义

`ChainModel.move_step(from_idx, to_idx)`（`chain_model.py:144-155`）实际是**交换两个 ACTION 节点的内容**（`action`/`comment`/`enabled`），不改 DAG 拓扑。对相邻 ±1 移动正确，但对「移动到指定序号 / 置顶 / 拖拽」会产生错误顺序（`[A,B,C,D]` 把 A 移到 2 位期望 `[B,C,A,D]`，swap(0,2) 却得 `[C,B,A,D]`）。

→ 必须新增 **insert 语义的统一重排原语**，复用既有的「交换节点内容、不动 DAG 边」模式（已验证安全）。

### 4.2 新增 API

| 方法 | 签名 | 语义 |
|---|---|---|
| `ChainModel.reorder_steps` | `(new_order: list[int]) -> None` | `new_order` 为「原索引的新排列」；按序把对应 ACTION 节点的 `action`/`comment`/`enabled` 重写到线性序列，不动 DAG 边。`_mark_dirty()` + 发 `CHAIN_STEPS_CHANGED`。 |
| `ChainModel.duplicate_step` | `(index: int) -> int` | `copy.deepcopy(steps[index])`，追加（`add_step`）后用 `reorder_steps` 把副本移到 `index+1`；返回副本新索引。越界返回 -1。 |
| `ActionChainController.reorder_steps` | `(new_order) -> None` | 透传 + `_require_idle()` |
| `ActionChainController.duplicate_step` | `(index) -> int` | 透传 + `_require_idle()` |
| `ActionChainController.move_to_index` | `(index, target) -> None` | 由「序号输入确定移动」调用：构造 new_order（insert 语义）后 `reorder_steps`。 |

> 既有 `move_step`（swap）保留，仅用于 ↑↓ 逐格相邻移动，语义正确零风险。

### 4.3 insert 语义构造（UI 层工具函数，共用）

放在 `step_param_view.py` 或 controller 内：

- `build_move_order(n, src, dst) -> list[int]`：把 `src` 取出插入到 `dst`，其余顺延。
- `build_top_order(n, idx)` / `build_bottom_order(n, idx)`：置顶 / 置底。
- `build_batch_move_order(n, selected_idxs, delta)`：选中项整体 ±1。

## 5. 步骤详情面板规格（Qt / tk 统一）

```
┌─ 步骤详情 ──────────────────────┐
│ [CLICK_IMAGE]          #3 / 12  │  类型胶囊 + 序号
│ 点击图片 btn.png · 左键          │  ← 摘要 describe（修 Qt 漏渲染 bug）
│ ─────────────────────────────── │
│ 序号 [ 3  ] ▾   [确定移动]       │  ← 输入目标序号(1~N)+确定 → move_to_index
│ ─────────────────────────────── │
│ ▼ 关键参数 (5)                  │  ← 默认展开，step_key_fields 配置驱动
│    模板图片      btn.png         │
│    匹配阈值      0.85            │
│    检测模式      未找到则跳过     │
│    偏移坐标      (+5, -3)        │
│    长按时长      0.5s            │
│ ▷ 全部字段 (10)                 │  ← 默认折叠，点开；dataclass 全字段
│ ─────────────────────────────── │
│ ☑ 启用        备注:[_________]  │
│  ↑ ↓  复制 编辑 删除             │  ← 复制 = 新增按钮
└────────────────────────────────┘
```

- **摘要**：`step.describe()`（Qt 补齐，与 tk 对齐）。
- **序号输入 + 确定移动**：SpinBox / 输入框预填当前序号（1-based），范围 `[1, N]`，确认后 `move_to_index(idx, target-1)`。
- **关键参数表**：见 §7。每行「中文标签 : 值」，默认展开。
- **全部字段**：`dataclasses.fields()` 遍历（排除 `ClassVar`），「字段名 : 格式化值」，默认折叠，标题显示字段计数。
- **启用 / 备注**：保留既有行为。
- **按钮**：↑ / ↓ / 复制 / 编辑 / 删除。

## 6. 步骤列表重排规格（Qt / tk 统一）

| 手段 | 行为 | 底层 |
|---|---|---|
| ↑ / ↓（保留） | 逐格相邻移动 | swap `move_step` |
| 输入目标序号 + 确定 | 取出插入目标位，其余顺延 | `move_to_index` → `reorder_steps` |
| 拖拽行 | 拖到新位释放，其余顺延 | `reorder_steps` |
| 多选（Ctrl/Shift）+ ↑↓ | 选中项整体上 / 下移一格 | `reorder_steps` |
| ⤒ 置顶 / ⤓ 置底 | 一键到首 / 末 | `reorder_steps` |

- 列表选中模式切换为支持多选（Qt `ExtendedSelection` / tk Treeview `extended`）。
- 拖拽：Qt 用 `QTreeWidget` 内部拖拽 + 自定义 `dropEvent` 触发 `reorder`；tk 用 `<Button-1>`/`<B1-Motion>`/`<ButtonRelease-1>` 手动实现。
- 执行中（`_require_idle`）所有写操作被拒，UI 给提示，不崩溃。

## 7. 关键参数配置（step_key_fields.py，共用）

集中表 `KEY_FIELDS: dict[ActionType, list[tuple[str, str]]]`，每项 `(字段名, i18n_key)`。

**字段选择规则**：用户最常调整的——坐标 / 阈值 / 时间 / 按键 / 检测模式 / 重试 / 方向。每类 4-6 项。

示例（实现时按 `step_types.py` 实际字段补全所有 ActionType）：

## 8. 值格式化（step_param_view.py，共用）

`format_field_value(step, field) -> str`：

- 枚举 → 友好名（复用 `describe` 内已有映射 / i18n；无法翻译时回退 `.name`）。
- 路径 → `os.path.basename`，空 → `t("common.not_set")`。
- `list` / `tuple` → 长度描述（如「3 项」）或简略。
- `None` → `"--"`。
- `bool` → `✓ / ✗`。
- 其他 → `str(value)`。

## 10. 测试策略（≥80% 覆盖，TDD）

**共用层（重点）**：
- `reorder_steps` insert 语义正确：对比 swap 的反例用例（`[A,B,C,D]` 移 A→2 得 `[B,C,A,D]`）。
- `reorder_steps` 不破坏 DAG：action 节点数、边数、start→...→end 连通性不变。
- `duplicate_step`：副本在 `index+1`、内容与原一致且独立（deepcopy）、越界返回 -1。
- `move_to_index` / 置顶 / 置底 / 批量移动 的 order 构造正确。
- `_require_idle`：运行中所有写操作抛 `RuntimeError`。

**UI**：Qt / tk 详情面板渲染了 describe / 关键参数 / 全部字段；序号移动 / 拖拽 / 批量 / 置顶置底触发正确 `reorder`；复制按钮产出副本。

## 11. 影响范围与风险

- **改动文件**：`chain_model.py`、`action_chain_controller.py`、新增 `step_key_fields.py` / `step_param_view.py`、`action_chain_props_mixin.py`（Qt 详情）、`step_property_panel.py`（tk 详情）、`action_chain_page.py`（Qt + tk 列表重排）、i18n `zh/en.json`。
- **风险**：`reorder_steps` 改节点内容——必须保证 `action_nodes()` 线性顺序稳定且与 UI 树表行序一致；拖拽 / 批量重排后选中状态恢复正确。
- **不动**：既有 `move_step`（swap）保留；DAG 拓扑（边）不被任何新 API 修改。
