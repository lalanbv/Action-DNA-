> 日期：2026-06-19

## 背景

`/simplify` 审查产出 4 项「附理由跳过」。本轮按用户要求逐项落地。原则：不盲目套用当初被否的提案（其中第 4 项的提案基于错误前提——混淆了「前缀文案」与「标签文案」的 i18n key），而是为每一项找到**真正更优**的实现。

## 逐项改动

### 1. `build_block_insert_order` — 命令式 flag+loop → 声明式切片

**文件**：`src/panel/components/step_param_view.py`

**当初被否理由**：声明式版的 `sel_before = target - 选中前置数` 索引算术更隐晦，非显然更优。

**本轮改法**（比被否提案更直白）：去掉可变 `inserted` 标志位与尾部 `if not inserted` 分支，改为「先取非选中余项、再在 `target` 位切片插入」。

```python
sel_set = set(sel)
# 非选中项保持原序;块插入位 = 原序小于 target 的非选中项个数(target==n 时为全部)
others = [i for i in range(n) if i not in sel_set]
insert_at = sum(1 for i in others if i < target)
return others[:insert_at] + sel + others[insert_at:]
```

- `sum(1 for i in others if i < target)` 直读为「原序小于 target 的非选中项个数」，比算术 `target - count` 清晰。
- 无可变状态，贴合不可变偏好；`target == n`（追加末尾）由 `insert_at == len(others)` 自然成立，无需特判。
- **回归兜底**：`TestBuildBlockInsertOrder` 全 5 例（单选插入/多选置顶/无选择/追加末尾/落在块内 noop）逐字等价，已跑通。

### 2. `field_value_i18n_key` — 去掉 `.get(field, {})` 的空 dict 分配

**文件**：`src/core/step_types.py`

**当初被否理由**：非热路径，Python 惯用法，trivial。

**本轮改法**：详情面板「全部字段」表对每个步骤的**每个字段**调 `format_field_value → field_value_i18n_key`，其中大量字段（`pos_x`/`pos_y`/`threshold`/`offset_*` 等）不在注册表中，原写法每次 miss 都 new 一个 throwaway `{}`。改为显式 `is not None` 判空，零分配：

```python
mapping = _FIELD_VALUE_I18N.get(field_name)
return mapping.get(raw) if mapping is not None else None
```

贴合用户的 0GC 偏好，且语义更明确。

### 3. `ClickPosStep.describe` — 修掉 `.get(default)` 每次必算 `t()` 的浪费

**文件**：`src/core/step_types.py`

**当初被否理由**：`button_prefix` 想复用 `_FIELD_VALUE_I18N["button"]`，但用的是 `dialog.btn.*`（标签）而非 `action.describe.*_prefix`（前缀），不同 key，超 scope。

**本轮改法**（正确处理两个子项）：

- **`click_labels` 真优化**：原 `click_labels.get(self.clicks, t("...multi_click...", count=...))` —— Python 中 `.get` 的 **default 实参每次都被求值**，即每次调用都算了 **4 次 `t()`**（字典里 3 个 + default 1 个）+ 1 次 dict 分配。改 `if/elif/else`，**只算 1 次 `t()`**：

  ```python
  if self.clicks == 1:
      click_label = t("action.describe.single_click")
  elif self.clicks == 2:
      click_label = t("action.describe.double_click")
  elif self.clicks == 3:
      click_label = t("action.describe.triple_click")
  else:
      click_label = t("action.describe.multi_click", count=self.clicks)
  ```

- **`button_prefix` 不复用注册表**（确认被否理由正确）：`action.describe.right_prefix`（「右键-」类**前缀**）与 `dialog.btn.right`（**标签**）语义不同，复用会输出错误文案。保持 `if/elif`（2 分支 + 默认值，已是最优形态），加注释说明「前缀≠标签、故不复用」以防后人重蹈。

### 4. `dropEvent` None 分支 — 去死赋值，统一走单一事实源

**文件**：`src/panel/qt_backend/pages/action_chain_page.py`

**当初被否理由**：`click_below = False` 属防御性初始化，两分支都赋值使变量恒定义，清晰。

**本轮改法**：`drop_insert_target(None, ...)` 对 `None` 短路返回 `n`，`click_below` 在该路径**根本不被读**，确为死赋值。但若在调用点直接 `target = n` 会把「None→n」语义**重复散落**到第二处（破坏单一事实源）。改为：None 分支也直接调 `drop_insert_target`，既删死赋值又保语义集中：

```python
if target_item is None:
    # 落到所有行下方空区:drop_insert_target 对 None 短路返回 n(追加末尾),
    # 第二参 False 为占位、此路径不被读
    target = drop_insert_target(None, False, n)
else:
    target_idx = self.indexOfTopLevelItem(target_item)
    click_below = pos.y() > self.visualItemRect(target_item).center().y()
    target = drop_insert_target(target_idx, click_below, n)
```

`target` 两分支均赋值恒定义；`click_below`/`target_idx` 收紧到真正使用它们的 else 分支内。
